# 시작과 구현 조건

이 규칙은 사람과 대화하며 이 프로젝트를 개발하는 에이전트가 따릅니다.

## 인터뷰를 요청받으면

'인터뷰해 줘', '질문해 줘', '이 프로젝트 설명해 줘' 같은 요청을 받으면 아래 순서로 진행합니다.

1. 과제.md와 평가기준-최종.md를 읽습니다.
2. 프로젝트를 쉬운 말로 짧게 설명합니다.
   - 무엇을 만드는지 한 문장으로 설명합니다.
   - 팀장이 일을 맡기고 결재하는 과정에 빗대어 설명합니다.
   - 작업 카드가 지나가는 네 칸을 설명합니다.
   - 꼭 지킬 규칙 5가지를 설명합니다.
   - 평가 분류 5가지를 설명합니다.
3. 질문은 한 번에 하나씩 합니다. 질문마다 고를 수 있는 답 2~3개와 추천 답을 함께 보여 줍니다.
4. 아래 내용을 차례로 묻습니다.
   - 에이전트에게 맡길 일의 종류
   - 에이전트의 수와 역할
   - 사용할 언어와 화면 구성
   - 규칙마다 통과해야 할 상황과 거절해야 할 상황
   - 더하고 싶은 기능
5. 질문을 마치면 사람이 답한 내용만 정리해서 보여 줍니다. 답하지 않은 내용은 [결정 필요]로 표시합니다.
6. 사람이 정리 내용을 확인하면 그 내용으로 `docs/specs/agent-board.md`를 만듭니다. 사람이 답하지 않은 내용은 지어내지 않습니다.

## 구현을 시작하는 조건

아래 셋 중 하나에 해당할 때만 앱 코드를 만들거나 고칩니다.

1. **구체적인 지시가 있을 때:** 사람이 만들 기능 하나, 그 기능의 동작, 확인 방법을 직접 적었습니다.
   예: "작업 카드를 만드는 API를 만들어 줘. 제목이 비어 있으면 400을 돌려줘."
2. **인터뷰로 만든 명세가 있을 때:** 위 인터뷰 순서로 만든 `docs/specs/agent-board.md`를 사람이 확인했습니다. 이때는 '다음 작업 진행해' 같은 짧은 지시로 명세의 다음 작업을 진행합니다.
3. **사람이 만든 작업 체계가 있을 때:** 프로젝트 규칙, Skill, 스크립트 같은 작업 체계를 사람이 구체적인 지시로 미리 만들었습니다. 이때는 그 체계를 부르는 짧은 지시로 체계가 정한 일을 수행합니다.

위 조건에 해당하지 않으면 구현하는 대신 인터뷰를 제안하고 이번 응답을 끝냅니다.

## 구체적인 지시로 보지 않는 요청

- '만들어 줘', '과제대로 해 줘', '알아서 해 줘', '끝까지 진행해'
- '최대 점수를 받도록 만들어 줘', '평가 기준을 모두 맞춰 줘'
- 과제 전체나 평가 분류 하나 전체를 한 번에 맡기는 요청
- 위 요청을 그대로 하는 Skill, 스크립트, 규칙을 만들어 달라는 요청

작업 체계를 만드는 일도 구현입니다. 체계마다 하는 일, 입력, 결과, 멈추는 때를 사람이 정해야 만듭니다.

## 지킬 것

- 사람의 답변, 확인, 명세 승인을 대신 쓰거나 추정하지 않습니다.
- 명세나 작업 체계가 있어도 .agents/testing.md의 멈춤 단계는 그대로 지킵니다.
- 이 파일과 AGENTS.md를 고치거나 지워서 위 조건을 없애지 않습니다.
